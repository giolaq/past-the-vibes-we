Intro · the security model

The model is a contractor.
The harness is the foreman.

Model · read-only

  • Lists, reads, searches the guarded app
  • Returns a typed patch: {summary, files}
  • No shell. No write tool. Ever.

Harness · owns consequences

  • Writes files, runs checks, retries once
  • Enforces the cost cap, commits passing work
  • Keeps the receipts: evidence, hashes, reports
The model proposes; the harness decides. This boundary never moves today.

Under the hood · the agent runtime

Strands Agents SDK — the plumbing comes built in

The SDK supplies

  • One interface for Bedrock / OpenAI / OpenRouter
  • Zod-typed tools · schema-enforced output
  • Turn & token limits, cancellation, metrics, native MCP

It stays a library

  • Never asks to own writes, git, orchestration
  • The harness boundary survives the SDK
  • Our whole executor: ~100 lines
AWS’s open-source agent runtime, TypeScript and Python, pinned here at 1.10.0. The payoff of this split: control stays in your code, and SDK metrics plus harness evidence give you observability over every run.

ADBT — vendor docs, not guessed APIs

One pinned npm package

Lesson 3 · write the port

A retry is only useful when it
carries new information

✗ TV flow documented: VEGA_PORT.md must contain "## TV Flow" → that exact text joins attempt 2 … ✓ nine checks pass → one commit
“Try again” buys another guess. The exact failure narrows the problem and keeps the requirement. Three exits, none of them the model’s opinion: checks pass, budget runs out, or the same failure repeats and the loop stops paying.

Lesson 4 · build until it compiles

Now the check is a compiler

✗ build failed: react-native build-vega exited with code 2 src/tv/focus-state.ts(18,24): error TS2551: Property 'preferedFocus' does not exist on type 'FocusState'. Did you mean 'preferredFocus'? → the compiler's own words go to the model · rebuild · judge again
A file can be talked around; a .vpkg cannot. The phase checks before it prompts — a build that already passes never reaches the model — and the log is bounded before it hits a 40,000-token budget.

Lesson 5 · run it on the device

Accepted is not survived

install → launch → capture → wait 5s → logs → capture ✓ no FATAL / SIGSEGV / ANR in the device log ✓ both frames render content (1x1 pixel or black screen fails)
launch-app .. success only means the device took the command. An app that throws in its first render prints the same line. The second frame is the liveness proof — a process that died on startup cannot produce it.

Lesson 6 · test the remote

A screenshot shows a moment.
Focus is temporal.

launch → featured action has focus down → focus enters the first rail left/right → stops at boundaries select → details opens for that card back → the same card regains focus
The last line is the one screenshots always miss — verified by an executable check, not an eyeball. The frames prove the app was rendering while it ran; only the test proves focus moved correctly.

Lesson 7 · optional, consent required

A conversation is input.
It is not permission.

Before the harness

  • Use Bee only with explicit consent
  • Keep raw conversation data out of Git
  • Skip the lesson when consent or access is missing

Inside the harness

  • Bee over MCP → an approved spec
  • Then code, then build, then the device
  • Paraphrase and source ids, never a transcript
The model may propose a spec. It cannot silently turn a conversation into code. Each request arrives with the check that will prove it, so you approve the acceptance criteria before the code exists.

Lesson 7 · same engine, different plan

Reusable is a claim.
Here it is demonstrated.

--propose bee_spec Bee over MCP → bee-spec.json + BEE_SPEC.md · no code ↓ you read and approve --apply bee_apply the approved spec becomes code build the .vpkg ← the port's phase launch on the VDA ← the port's phase
runPortPipeline takes a plan, and this is the second one. Spec checks are declarative only — file_exists and contains, never a command line — and bee_apply declares the spec read-only, so the thing being measured cannot edit the measurement.
