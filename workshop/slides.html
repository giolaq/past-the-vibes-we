Introduction · the security boundary

The model proposes.
The harness controls changes.

Model: read-only

  • Lists, reads, and searches the guarded app.
  • Returns a typed patch: {summary, files}.
  • Has no shell or write tool.

Harness: controls effects

  • Writes files, runs checks, and retries.
  • Applies the cost limit and commits passed work.
  • Records evidence, hashes, and reports.
The model proposes. The harness decides. This boundary does not change.
introductionKeep this boundary in every phase.

Architecture · the agent runtime

Strands Agents SDK
runs the model and tool loop

Strands supplies

  • One interface for Bedrock, OpenAI, and OpenRouter.
  • Zod-typed tools and schema-enforced output.
  • Limits, cancellation, metrics, and MCP.

The harness supplies

  • Writes, Git, phase order, and checks.
  • One stable security boundary.
  • An executor of approximately 100 lines.
The repository pins the TypeScript SDK at 1.10.0. The SDK reports model activity. The harness keeps control of effects.

Lesson 4 · build until it compiles

Now the check is a compiler

$ inject-build-failure workshop # guarded copy only ✗ src/workshop-build-break.ts(2,14): error TS2322: Type 'number' is not assignable to type 'string'. → the compiler's own words go to the model · rebuild · judge again
The injected failure is deterministic. The phase checks before it calls the model. It sends the exact diagnostic and commits only after the build passes.

Appendix A1 · optional, consent required

A conversation is input.
It is not user approval.

Before the harness

  • Get explicit consent.
  • Keep conversation data out of Git.
  • Skip the lesson if consent or access is missing.

Inside the harness

  • Bee over MCP produces a proposed specification.
  • The user approves before source changes.
  • Store summaries and source IDs. Do not store a transcript.
The model can propose a specification. The user must approve the checks before the harness changes source.
